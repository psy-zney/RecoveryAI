# AI-Driven Disk Forensics & Data Recovery MCP Engine
> **Kiến trúc:** Hybrid Brain & Muscle (AI Control Plane + Rust/C++ SIMD Data Plane)  
> **Giao thức:** Model Context Protocol (MCP) qua JSON-RPC 2.0 (`stdio`)  
> **Nguyên tắc an toàn:** 100% Read-Only Physical I/O + In-Memory Copy-on-Write (Virtual Patching)

## 1. Tổng quan Kiến trúc Hệ thống (System Architecture)

Hệ thống tách biệt hoàn toàn việc xử lý dữ liệu nhị phân khổng lồ (hàng tỷ sector) khỏi Context Window của AI Agent:
* **Muscle (Tầng C++/Rust Native):** Đọc đĩa trực tiếp qua DMA (`FILE_FLAG_NO_BUFFERING`), chống treo I/O khi gặp Bad Sector, quét chữ ký file bằng tập lệnh vector SIMD (`AVX2`/`SSE4.2`), tính toán Shannon Entropy ($0.0 - 8.0\text{ bits/byte}$), giải mã cấu trúc hệ thống tệp (`MBR`, `GPT`, `NTFS $MFT`, `FAT32/exFAT`) và lọc sơ bộ các cluster bị phân mảnh.
* **Bridge (Tầng MCP Server):** Quản lý phiên làm việc (Stateful Session), chạy các tác vụ quét đĩa ngầm (Async Job Queue chống timeout), duy trì bộ nhớ đệm **Virtual Overlay (RAM Patch Map)** và chỉ trích xuất **Metadata JSON siêu gọn (< 5KB)** gửi cho AI.
* **Brain (AI Agent + `SKILL.md`):** Đọc báo cáo bất thường (Anomaly Report), suy luận nguyên nhân hỏng phân vùng/hệ thống tệp, ra lệnh vá thử nghiệm trên RAM và điều phối các engine mã nguồn mở (`The Sleuth Kit`, `PhotoRec`, `ddrescue`) trích xuất dữ liệu.

## 4. Triển khai Chi tiết các Cơ chế Cốt lõi (Core Implementation Blueprints)

### 4.1. Bộ đệm Căn chỉnh 4KB & Mở Đĩa Thô An toàn (`crates/core-io/src/aligned_buffer.rs`)
Khi mở `\\.\PhysicalDriveX` với cờ `FILE_FLAG_NO_BUFFERING`, Windows bắt buộc địa chỉ bộ nhớ RAM và số byte đọc phải chia hết cho kích thước Sector vật lý (512 hoặc 4096 bytes):

```rust
use std::alloc::{alloc_zeroed, dealloc, Layout};
use std::ops::{Deref, DerefMut};

pub const PAGE_ALIGNMENT: usize = 4096;

pub struct AlignedBuffer {
    ptr: *mut u8,
    layout: Layout,
    len: usize,
}

impl AlignedBuffer {
    pub fn new(size: usize) -> Self {
        // Làm tròn kích thước lên bội số gần nhất của 4096 bytes
        let aligned_size = (size + PAGE_ALIGNMENT - 1) & !(PAGE_ALIGNMENT - 1);
        let layout = Layout::from_size_align(aligned_size, PAGE_ALIGNMENT)
            .expect("Invalid memory alignment layout");
        let ptr = unsafe { alloc_zeroed(layout) };
        if ptr.is_null() {
            std::alloc::handle_alloc_error(layout);
        }
        Self { ptr, layout, len: aligned_size }
    }
}

impl Deref for AlignedBuffer {
    type Target = [u8];
    fn deref(&self) -> &[u8] {
        unsafe { std::slice::from_raw_parts(self.ptr, self.len) }
    }
}

impl DerefMut for AlignedBuffer {
    fn deref_mut(&mut self) -> &mut [u8] {
        unsafe { std::slice::from_raw_parts_mut(self.ptr, self.len) }
    }
}

impl Drop for AlignedBuffer {
    fn drop(&mut self) {
        unsafe { dealloc(self.ptr, self.layout) };
    }
}
```

### 4.2. Cơ chế Virtual Overlay — Vá lỗi trên RAM (`crates/core-io/src/virtual_overlay.rs`)
Đảm bảo AI có thể thử nghiệm phục hồi MBR, GPT hoặc Boot Sector thoải mái mà **không bao giờ ghi một bit nào xuống USB thật**:

```rust
use std::collections::BTreeMap;

pub const SECTOR_SIZE: usize = 512;

pub trait RawStorageReader {
    fn read_physical_sectors(&mut self, start_lba: u64, count: usize, buf: &mut [u8]) -> std::io::Result<()>;
}

pub struct VirtualDiskOverlay<R: RawStorageReader> {
    physical_reader: R,
    // Lưu các sector đã được AI "vá" thử nghiệm trên RAM
    ram_patches: BTreeMap<u64, [u8; SECTOR_SIZE]>,
}

impl<R: RawStorageReader> VirtualDiskOverlay<R> {
    pub fn new(reader: R) -> Self {
        Self {
            physical_reader: reader,
            ram_patches: BTreeMap::new(),
        }
    }

    /// AI gọi hàm này qua MCP để áp dụng bản vá ảo lên RAM
    pub fn apply_virtual_patch(&mut self, lba: u64, offset_in_sector: usize, patch_bytes: &[u8]) -> std::io::Result<()> {
        let mut sector_buf = [0u8; SECTOR_SIZE];
        if let Some(existing) = self.ram_patches.get(&lba) {
            sector_buf.copy_from_slice(existing);
        } else {
            self.physical_reader.read_physical_sectors(lba, 1, &mut sector_buf)?;
        }

        let end = (offset_in_sector + patch_bytes.len()).min(SECTOR_SIZE);
        sector_buf[offset_in_sector..end].copy_from_slice(&patch_bytes[..(end - offset_in_sector)]);
        self.ram_patches.insert(lba, sector_buf);
        Ok(())
    }

    /// Mọi trình Parser (MBR, NTFS, FAT32) đều đọc qua hàm này
    pub fn read_sectors(&mut self, start_lba: u64, count: usize, out_buf: &mut [u8]) -> std::io::Result<()> {
        // 1. Đọc dữ liệu gốc từ đĩa vật lý
        self.physical_reader.read_physical_sectors(start_lba, count, out_buf)?;

        // 2. Ghi đè các sector đã được AI vá trên RAM vào buffer trả về
        for i in 0..count {
            let current_lba = start_lba + i as u64;
            if let Some(patched_sector) = self.ram_patches.get(&current_lba) {
                let offset = i * SECTOR_SIZE;
                out_buf[offset..offset + SECTOR_SIZE].copy_from_slice(patched_sector);
            }
        }
        Ok(())
    }

    /// Xóa toàn bộ bản vá nếu AI nhận thấy hướng tiếp cận chưa đúng
    pub fn rollback_all_patches(&mut self) {
        self.ram_patches.clear();
    }
}
```

### 4.3. Giải mã Zero-Copy & Tính Shannon Entropy (`crates/disk-parsers/src/ntfs_parser.rs`)
Ép kiểu trực tiếp 512 bytes của Sector thành cấu trúc Boot Sector của NTFS và đo độ hỗn loạn dữ liệu:

```rust
use zerocopy::{FromBytes, Immutable, KnownLayout, Unaligned};

#[repr(C, packed)]
#[derive(FromBytes, Immutable, KnownLayout, Unaligned, Debug)]
pub struct NtfsBootSector {
    pub jump_instruction: [u8; 3],
    pub oem_id: [u8; 8],              // Phải là "NTFS    "
    pub bytes_per_sector: u16,        // Thường là 512 hoặc 4096
    pub sectors_per_cluster: u8,
    pub reserved_sectors: u16,
    pub always_zero_1: [u8; 3],
    pub not_used_1: u16,
    pub media_descriptor: u8,         // 0xF8 cho ổ cứng
    pub always_zero_2: u16,
    pub sectors_per_track: u16,
    pub number_of_heads: u16,
    pub hidden_sectors: u32,
    pub not_used_2: u32,
    pub not_used_3: u32,
    pub total_sectors: u64,
    pub mft_lcn: u64,                 // Logical Cluster Number của $MFT
    pub mft_mirr_lcn: u64,            // Logical Cluster Number của $MFTMirr
    pub clusters_per_mft_record: i8,
    pub not_used_4: [u8; 3],
    pub clusters_per_index_record: i8,
    pub not_used_5: [u8; 3],
    pub volume_serial_number: u64,
    pub checksum: u32,
    pub bootstrap_code: [u8; 426],
    pub end_of_sector_marker: u16,    // Phải là 0xAA55 (Little Endian)
}

/// Tính Shannon Entropy chuẩn trong thang [0.0, 8.0] bits/byte
pub fn calculate_shannon_entropy(data: &[u8]) -> f64 {
    if data.is_empty() {
        return 0.0;
    }
    let mut counts = [0usize; 256];
    for &b in data {
        counts[b as usize] += 1;
    }
    let len = data.len() as f64;
    let mut entropy = 0.0;
    for &c in &counts {
        if c > 0 {
            let p = (c as f64) / len;
            entropy -= p * p.log2();
        }
    }
    entropy
}
```

## 5. Thiết kế Giao thức MCP & Danh sách Tools (MCP Specification)

Để AI Agent điều khiển hệ thống mượt mà, không bị tràn Context Window và không bao giờ bị Timeout khi quét đĩa dung lượng lớn, MCP Server cung cấp **8 Tools chuẩn hóa** chia theo 4 nhóm:

### Nhóm 1: Khởi tạo & Chẩn đoán Tổng thể (Triage & Overview)
| Tên MCP Tool | Tham số đầu vào (Arguments) | Chức năng & Dữ liệu JSON trả về (< 2KB) |
|---|---|---|
| `open_recovery_session` | `target_path`: Đường dẫn `\\.\PhysicalDriveX` hoặc file `.img` | Mở thiết bị ở chế độ Read-Only DMA, khởi tạo `VirtualDiskOverlay` trên RAM, trả về `session_id`, dung lượng vật lý, kích thước sector và trạng thái S.M.A.R.T / I/O cơ bản. |
| `scan_disk_topology` | `session_id` | Quét nhanh LBA 0 (MBR), LBA 1..33 (GPT), LBA cuối đĩa (Backup GPT/VBR) và các offset phân vùng phổ biến (LBA 63, 2048). Trả về bản đồ trạng thái (`VALID`, `ZEROED`, `CORRUPTED`) kèm gợi ý bất thường. |

### Nhóm 2: Phân tích Chuyên sâu & Khám nghiệm Cấu trúc (Deep Inspection)
| Tên MCP Tool | Tham số đầu vào (Arguments) | Chức năng & Dữ liệu JSON trả về (< 3KB) |
|---|---|---|
| `inspect_sector_structure` | `session_id`, `lba`, `parse_as` (`RAW_HEX` \| `MBR` \| `GPT` \| `NTFS_VBR` \| `FAT32_BPB` \| `MFT_ENTRY`) | Giải mã sector tại `lba` theo struct chỉ định. Chỉ rõ từng trường hợp lệ và **highlight trường bị hỏng** (ví dụ: `bytes_per_sector = 0`), kèm bản tóm tắt Entropy ($0.0 - 8.0$). |
| `scan_filesystem_journals` | `session_id`, `partition_start_lba` | Quét vùng `$MFTMirr`, `$UsnJrnl` và các chỉ mục thư mục `$I30` (NTFS) hoặc bảng FAT thứ 2 (FAT32) để tìm danh sách các file vừa bị xóa hoặc bị ghi đè bảng mục lục chính. |

### Nhóm 3: Tác vụ Quét Ngầm Bất đồng bộ (Async SIMD Jobs — Chống Timeout)
| Tên MCP Tool | Tham số đầu vào (Arguments) | Chức năng & Dữ liệu JSON trả về (< 2KB) |

# Quy chuẩn Điều tra & Khôi phục Dữ liệu Cấp thấp (Forensic Recovery Protocol)

Bạn là một Chuyên gia Khôi phục Dữ liệu Hệ thống (Digital Forensics & Recovery Specialist) điều khiển Native Engine (Rust/SIMD) thông qua MCP.

## 3 Luật Bất biến (Golden Rules)
1. **Không bao giờ ghi lên thiết bị gốc:** Mọi thử nghiệm khôi phục MBR, GPT, Boot Sector (VBR) hoặc nối cluster BẮT BUỘC phải thực hiện qua `virtual_patch_and_verify` (chạy trên RAM Overlay).
2. **Evidence-Based Reasoning (Suy luận dựa trên bằng chứng):** Không đoán mò địa chỉ LBA. Luôn kiểm tra chữ ký hex (`0x55AA`, `NTFS    `, `MSDOS5.0`, `EXFAT   `, `FILE0`) và kiểm tra tính toán học của các trường trong Struct trước khi kết luận.
3. **Bảo vệ phần cứng lỗi:** Nếu phát hiện `bad_sectors_count > 0` hoặc độ trễ đọc sector tăng đột biến (`> 200ms`), lập tức dừng mọi lệnh quét sâu và yêu cầu chạy `start_async_disk_job(job_type="DD_RESCUE_CLONE")` để tạo file ảnh `.img` trước.

## Quy trình Chẩn đoán 4 Bước (Standard Operating Procedure)

### Bước 1: Mở phiên & Quét Topology (`open_recovery_session` -> `scan_disk_topology`)
- Xác định kích thước ổ đĩa, kích thước sector (`512` hay `4096` bytes) và kiểm tra tình trạng sức khỏe I/O.
- Đọc báo cáo `scan_disk_topology` để phân loại tình huống lỗi vào 1 trong 4 kịch bản dưới đây.

### Bước 2: Xử lý theo Kịch bản Lỗi (Scenario Playbooks)

#### Kịch bản A: Mất phân vùng / Unallocated (Hỏng MBR hoặc GPT tại LBA 0..33)
1. Kiểm tra trường `gpt_backup_header` ở LBA cuối cùng của ổ đĩa trong báo cáo `scan_disk_topology`. Nếu còn nguyên vẹn (`VALID`), dùng `virtual_patch_and_verify` để phục hồi bảng phân vùng từ bản Backup GPT.
2. Nếu cả MBR và Backup GPT đều bị xóa trắng (`ZEROED`), gọi `start_async_disk_job(job_type="SIMD_VBR_HUNT")` để tầng Rust quét tìm các Volume Boot Record (VBR) bị mồ côi trên đĩa.
3. Từ vị trí LBA của VBR tìm được và trường `total_sectors` bên trong VBR đó, tính toán lại `Start LBA` và `End LBA` rồi dựng lại Partition Entry trong MBR/GPT trên RAM.

#### Kịch bản B: Ổ đĩa biến thành định dạng RAW / Chặn truy cập (Hỏng VBR hoặc $MFT đầu)
1. Gọi `inspect_sector_structure` tại `Start LBA` của phân vùng (thường là LBA `2048`).
2. **Nếu là NTFS:**
   - Kiểm tra LBA cuối cùng của phân vùng (hoặc `End LBA - 1`) — nơi NTFS luôn lưu bản sao dự phòng của Boot Sector (`Backup VBR`).
   - Nếu VBR chính bị hỏng nhưng Backup VBR còn tốt, gọi `virtual_patch_and_verify(copy_from_lba=backup_vbr_lba, to_lba=primary_vbr_lba)`.
   - Nếu bảng `$MFT` chính bị lỗi ở những bản ghi đầu tiên (Record 0..3), đọc vị trí `mft_mirr_lcn` trong VBR để lấy 4 bản ghi dự phòng từ `$MFTMirr`.
3. **Nếu là FAT32 / exFAT:**
   - Kiểm tra Sector `Start LBA + 6` (với FAT32) hoặc `Start LBA + 12` (với exFAT) để lấy Backup Boot Sector đè lên Sector đầu của phân vùng trên RAM.

#### Kịch bản C: Xóa nhầm File hoặc Quick Format (Cấu trúc phân vùng vẫn còn)
1. Gọi `scan_filesystem_journals` để quét các bản ghi `$MFT` có cờ `Unallocated`, nhật ký `$UsnJrnl` và vùng chỉ mục thư mục `$I30`.
2. Kiểm tra xem các cluster dữ liệu của file bị xóa đã bị ghi đè chưa bằng cách kiểm tra trạng thái cấp phát và tính Entropy.
3. Dùng `extract_recovered_data(mode="TSK_TREE_EXTRACT")` để lấy lại file nguyên gốc kèm tên và đường dẫn thư mục.

#### Kịch bản D: Mất sạch bảng mục lục / File bị phân mảnh (Raw Carving & Defragmentation)
1. Khi bảng `$MFT` hoặc `FAT` đã bị ghi đè hoàn toàn, gọi `start_async_disk_job(job_type="SIMD_MAGIC_CARVE")` để quét chữ ký file.
2. Nếu một file quan trọng (như video `.mp4`, file nén `.zip`, cơ sở dữ liệu `.sqlite`) bị đứt đoạn do phân mảnh:
   - Gọi `start_async_disk_job(job_type="FRAGMENT_PREFILTER")` để tầng Rust lọc ra **Top 5 cluster ứng viên** có độ khớp biên (Boundary Coherence & Entropy continuity) cao nhất.
   - Đọc mẫu byte ở phần đuôi mảnh đầu và phần đầu của 5 ứng viên qua `inspect_sector_structure`, đối chiếu với đặc tả định dạng (ví dụ: cấu trúc `moov`/`mdat` atom của MP4) để chọn đúng mảnh ghép và gọi `extract_recovered_data(mode="CARVE_BY_LBA_RANGES")`.
